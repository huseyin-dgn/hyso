# HYSo 0.2.0 - Release support scope

Canonical source: `docs/user-guide/content.json` ? `release_support`; the packaged registry, public `analysis.feature_catalog(...).to_dict()['release_support']`, CLI `hyso analysis show P23 --json`, and four-language offline guide expose the same policy.

SUPPORTED applies only to the verified scope below. PARTIAL means limited coverage, BLOCKED is a safety/admission refusal, UNSUPPORTED is outside release scope, DEFERRED is intentionally postponed. CPU/CUDA columns describe new measurement where applicable; device-independent/offline support is explicitly identified. Native `supported_devices` lists backend capability, not release acceptance. No FULL CUDA ACCEPTANCE is claimed.

The completed evidence remains 8536 source PASS / 13 risky integrations BLOCKED / 55 infrastructure PASS / 36 package PASS / 1 historical AST RETIRED. P23/P31 historical PARTIAL is unchanged. This policy does not relabel BLOCKED results as PASS. Subsequent scope changes need only the targeted verification plan; old acceptance receipts remain immutable evidence for the tested snapshot.

Existing CPU/GPU journals remain readable. Short GPU telemetry/trend captures serving independent features remain available under their original admission rules; they do not establish P31 long-run acceptance.

Analyzer/Advisor remain read-only. Builder/Trainer and normal CUDA training are independent and retained. All 35 IDs stay registered; no P feature or risk test is removed. B4 root-cause investigation is paused, not resolved.

## Current bounded CUDA evidence (U15–U18 reconciliation)

The original acceptance tables above remain historical. The support registry now
adds `current_cuda_acceptance` entries for the 32 P features with retained PASS
captures from `outputs/cuda-functional-acceptance-20261126/checkpoint.json`.
Each entry binds its evidence path and SHA256. These are exact recorded
model/device/runtime/protocol observations, not general hardware certification.
P23 covers only its basic path with `saved_activation_lifetime=false`, B4 closed.
P18 advanced counters, P31 CUDA 7200s and P33 advanced energy remain deferred;
`full_cuda_acceptance=false`. U01–U14 records and failed attempts are unchanged.
See [product experience acceptance](product-experience-acceptance.md) for the
separate CPU/offline campaign and export preinventory.
