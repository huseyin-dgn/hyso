# HYSo 0.2.0 — Draft release notes

**Proposed version only: not approved, tagged or published.** Package metadata
remains 0.1.6. This draft describes the development branch, not the current PyPI release.

- Training correctness: sample-weighted gradient accumulation and tail flushing,
  validation behavior and independent EarlyStopping best-state snapshots.
- AMP and scheduling: device-aware AMP, correct unscale/clipping/update ordering,
  OneCycle update budget and overflow-aware scheduler steps.
- EMA: preserve parameter decay and copy registered buffers, including BatchNorm
  running statistics and integer counters; honor optional EMA selection.
- Full-state checkpoint v1: state_dict-based model/optimizer/scheduler/scaler/EMA,
  epoch/history/metrics and optional RNG; atomic save, strict weights-only load.
  Legacy model-only checkpoint format stays separate and unchanged.
- EBO training resume: optional keyword-only `save_last_to`/`resume_from`, original
  total epoch budget, history and RNG continuation at completed epoch boundaries.
- ImageFolder/Subset resume: ordered dataset/indices/class-map validation and
  bounded torchvision v1 transforms in standard single-process loaders.
- Packaging: canonical root wheel/sdist builds, correct hyso namespace, declared
  torchsummary dependency and restored published model export list/order.

**Compatibility change:** minimum Torch requirement moves from >=1.13 to >=2.0.
Existing training results may change due to correctness fixes. Existing public
positional APIs and model state_dict schemas are retained; this is not a blanket
guarantee of unchanged numerical behavior for historical training workflows.

Verified reference: Windows / Python 3.10.18 / Torch 2.5.1+cu121 /
torchvision 0.20.1+cu121; CPU and RTX 3060 Laptop FP16 CUDA. Python>=3.8 is metadata,
not proof of minimum-runtime support. Python 3.8/Torch 2.0 runtime and clean
dependency installation remain unverified release gates.

Resume requires the same model/plan/data/runtime profile, num_workers=0, standard
sampler/collate and supported transforms. No mid-epoch, multi-worker, custom
dataset/transform, stateful callback or multi-GPU resume. CEMO/CNNS fit resume is
not included. ImageFolder uses path/size/mtime metadata, not image-content integrity
verification. CUDA AdaptiveMaxPool determinism remains an upstream limitation.

Before publishing: resolve the new version identity, finish minimum/clean-install
validation or decide the support policy, and repeat the final release quality gate.
