# HYSo 0.2.0 — Draft release notes

**Release candidate preparation: not tagged, released or published to PyPI.**
Local package metadata is 0.2.0. This draft describes the development branch;
the published package remains 0.1.6. Candidate preparation does not authorize publication.

- Training correctness: sample-weighted gradient accumulation and tail flushing,
  validation behavior and independent EarlyStopping best-state snapshots.
- AMP and scheduling: device-aware AMP, correct unscale/clipping/update ordering,
  OneCycle update budget and overflow-aware scheduler steps.
- EMA: preserve parameter decay and copy registered buffers, including BatchNorm
  running statistics and integer counters; honor optional EMA selection.
- Full-state checkpoint v1: state_dict-based model/optimizer/scheduler/scaler/EMA,
  epoch/history/metrics and optional RNG; atomic save, strict weights-only load.
  Legacy model-only checkpoint format stays separate and unchanged.
- OneCycleLR compatibility: normalize the trusted legacy annealing callable used
  by Torch 2.2.2 to a plain cos/linear strategy, restoring the local scheduler's
  native representation on load. Torch 2.2.2 and 2.5.1 checkpoint/resume were
  verified; format v1 and weights_only=True remain unchanged. No arbitrary callable
  serialization, unsafe load fallback or guarantee for unknown future scheduler schemas.
- EBO training resume: optional keyword-only `save_last_to`/`resume_from`, original
  total epoch budget, history and RNG continuation at completed epoch boundaries.
- ImageFolder/Subset resume: ordered dataset/indices/class-map validation and
  bounded torchvision v1 transforms in standard single-process loaders.
- Packaging: canonical root wheel/sdist builds, correct hyso namespace, declared
  torchsummary dependency and restored published model export list/order.

**Compatibility change:** Python>=3.10, Torch>=2.2.2 and torchvision>=0.17.2
are the candidate minimums, replacing published 0.1.6's Python>=3.8/Torch>=1.13.
Python 3.8/3.9 and Torch 1.x/2.0/2.1 users need a runtime upgrade or a suitable
older HYSo version. Match Torch and torchvision versions and CPU/CUDA channels:
2.2.2/0.17.2 and 2.5.1/0.20.1 are the tested pairs. These minimums do not mean
every newer version combination is verified.
Existing training results may change due to correctness fixes. Existing public
positional APIs and model state_dict schemas are retained; this is not a blanket
guarantee of unchanged numerical behavior for historical training workflows.

Verified older CPU profile: Windows x64 / Python 3.10.18 / Torch 2.2.2+cpu /
torchvision 0.17.2+cpu / NumPy 1.26.4, including installed-wheel checkpoint/resume.
Use NumPy 1.26.4 constraints to reproduce that profile; older Torch binaries with
NumPy 2 remain an ABI risk. No global NumPy<2 restriction is added.

Reference: Windows / Python 3.10.18 / Torch 2.5.1+cu121 / torchvision 0.20.1+cu121 /
NumPy 2.2.2; CPU and previously verified RTX 3060 Laptop FP16 CUDA (P0.6-C1).
GPU results are prior evidence; final actual CUDA verification belongs to P0.6-E.
Python 3.8/Torch 2.0 runtime was not tested and is outside this candidate policy.
P0.6-C's constrained offline clean dependency installation and the current target
wheel verification are distinct evidence; unconstrained online installation and
the broad Python/Torch version matrix remain unverified.

Resume requires the same model/plan/data/runtime profile, num_workers=0, standard
sampler/collate and supported transforms. No mid-epoch, multi-worker, custom
dataset/transform, stateful callback or multi-GPU resume. CEMO/CNNS fit resume is
not included. ImageFolder uses path/size/mtime metadata, not image-content integrity
verification. CUDA AdaptiveMaxPool determinism remains an upstream limitation.

The candidate uses the new 0.2.0 identity and the support policy selected in P0.6-D.
Before publishing: finish P0.6-E's final CPU/CUDA and final-artefact quality gate,
review the exact tested profiles and remaining installation limits, and obtain
separate publication authorization. See the [README](../../README.md) and
[candidate report](../audit/p0.6-d-release-candidate.md).
