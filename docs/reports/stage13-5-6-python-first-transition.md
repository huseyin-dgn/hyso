## 6. Graph / Trainer / Evaluation / Benchmark integration

`GraphTensorOutput(graph, output_name, task=None)` validates a real GraphModel, exactly one graph input and a real named output. It registers the **same graph object** and parameters. Its forward returns the selected Tensor while the original graph continues computing all configured outputs. No detach, weight copy, cast or device transfer is performed.

For classification training, use `task="multiclass"` or `task="binary"`; the selected output must reference a compatible classification_head. Unknown names, unsupported tasks, wrong head widths and multi-input graphs fail explicitly. Inference/benchmark selection may use another Tensor output without claiming regression/embedding training support.

Real tests verified parameter identity, input/parameter gradients, float64 propagation and strict wrapper state_dict loading. Wrapper keys use a `graph.` prefix; use matching wrappers or the graph's own state_dict when exchanging with an unwrapped graph. Training updates shared graph weights. Existing isolated inference and benchmark state guards remain unchanged.

## 13. Remaining technical limits and stopping the old server

The output adapter supports a single Tensor input and explicit classification training, not multi-input/multi-loss orchestration or general regression/embedding training. Bounded checks use eval-mode synthetic zero inputs and a sum-of-outputs gradient objective; they do not establish dataset quality, training-loss validity or every parameter's gradient coverage. Existing CPU/dtype/automatic-resume and native evidence restrictions remain.

Complete registered-model internal node/branch topology is not expanded by configuration-only comparison; those fields remain unavailable rather than zero. Metadata comparison does not infer performance. Missing runtime geometry/budgets skip checks explicitly. Exact counting is opt-in and limited to a known <=1M Core bound. Caller IDs/config digests do not attest trained-model/data origin.

The pre-existing **8765 server was not terminated**. Its loaded Python code/assets can remain in process memory even though the product source is removed. The observed listener belonged to PID 26404 at the read-only check; do not assume that PID remains valid later. Stop it in its own launching terminal with **Ctrl+C**. Do not restart it with `python -m hyso.studio`; that entry point is retired. The SQLite directory should remain untouched.
