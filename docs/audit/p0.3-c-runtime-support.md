## 1. Destek politikası

Üç seviye ayrı tutulmalıdır:

- **Runtime doğrulanmış referans:** Aşağıdaki tam Windows/CPU kombinasyonu. Bu çalışmada kullanıcılara runtime kanıtıyla önerilebilen kombinasyon budur.
- **Metadata/API bakımından uyumlu aday:** Dependency koşulları, resmî sürüm eşleşmesi ve gerekli API yüzeyi uyumlu; HYSo runtime başarısı henüz kanıtlanmış değil.
- **Test edilmemiş:** Diğer Python/Torch sürümleri, işletim sistemleri ve gerçek CUDA çalışması. Metadata alt sınırı, bütün üst sürümlerin test edildiği anlamına gelmez.

Python>=3.8, torch>=2.0 ve torchvision>=0.14 beyanları korundu. Python 3.8 için bu çalışmanın kanıtı kaynak syntax ve upstream metadata düzeyindedir; “runtime'da doğrulandı” denemez.

## 4. Test edilemeyen kombinasyonlar

Python launcher, gözlenen yerel Conda env dizinleri ve bilinen harici test interpreter'ı hedefli kontrol edildi. Bulunan sürümler 3.10.11, 3.10.18, 3.10.19 ve 3.13.12; **Python 3.8 bulunmadı**. Diğer interpreter'larda Torch/torchvision yok; tam runtime yalnız torch_gpu ve onu kullanan harici test ortamında var.

**Torch 2.0.x runtime'ı da yok.** Yeni interpreter, büyük paket veya CUDA wheel indirilmedi; mevcut ortam değiştirilmedi. Dokuz üretim Python dosyası Python 3.8 grammar ile parse edildi; bu bir Python 3.8 import/training testi değildir.

Mevcut NumPy, matplotlib ve scikit-learn sürümleri Requires-Python>=3.10 bildiriyor. Dolayısıyla doğrulanan tüm dependency kümesi Python 3.8'e aynen taşınamaz; daha eski uyumlu dependency sürümlerinin çözülmesi ve çalıştırılması gerekir.

## 5. Metadata ve training core değerlendirmesi

**Metadata düzeltmesi yapılmadı:** Bu görevde değişiklik gerektiren kanıtlanmış yeni bir üretim/metadata hatası bulunmadı. Mevcut gereksinimlerin birlikte çözümü mümkün; düşük torchvision adaylarının kendi Torch pinleriyle elenmesi beklenir.

EBO.fit OneCycle yolu `register_step_post_hook` kullanıyor. Bu metot [Torch 1.13.1'de yok](https://github.com/pytorch/pytorch/blob/v1.13.1/torch/optim/optimizer.py), [2.0.0'da var](https://github.com/pytorch/pytorch/blob/v2.0.0/torch/optim/optimizer.py). Üretimdeki `torch.amp.autocast` ve `torch.cuda.amp.GradScaler` scale/unscale_/step/update/get_scale API'leri de 2.0.0 kaynaklarında mevcut. **Core, incelenen API yüzeyi bakımından 2.0 ile uyumlu görünüyor; bu runtime kanıtı değil.** torch>=2.0 korunmalıdır.

Önemli test sınırı: `tests/test_scheduler_regression.py:290` native CPU overflow kontrolünde `torch.amp.GradScaler("cpu")` kullanıyor. [Torch 2.0.0 torch.amp modülü](https://github.com/pytorch/pytorch/blob/v2.0.0/torch/amp/__init__.py) bu sınıfı export etmiyor. Bu test harness'i minimum sürüme doğrudan taşınabilir sayılmamalı; üretimde kullanılan [CUDA scaler API'si](https://github.com/pytorch/pytorch/blob/v2.0.0/torch/cuda/amp/grad_scaler.py) ayrıdır. Testlerin daha yeni API kullanması tek başına üretim metadata alt sınırını yükseltme gerekçesi değildir. Test gevşetilmedi veya skip eklenmedi.

Diğer runtime bağımlılıkları kaynakta kullanılıyor. Üst sınır olmaması bütün kombinasyonların doğrulandığı anlamına gelmez. Özellikle eski Torch + NumPy 2 binary/ABI uyumluluğu bu ortamda sınanmadı; [NumPy'nin downstream ABI açıklaması](https://numpy.org/doc/2.0/user/troubleshooting-importerror.html) nedeniyle bu bir release riski olarak izlenmelidir. Bu genel ABI riskinden belirli bir HYSo hatası sonucu çıkarılmadı; kanıtsız global NumPy kısıtı eklenmedi.

## 7. Yeni release için kalan riskler

Minimum Python/Torch runtime ve tam dependency resolver/install doğrulaması; minimum sürüme uygun test harness kapsamı; eski Torch/NumPy ABI matrisi; gerçek CUDA ve diğer platform binary eşleşmeleri açık kalır. P0.3-B'nin mevcut dependency kümesi üzerindeki resolver kontrolü temiz kurulum kanıtına yükseltilmedi.

PyPI 0.1.6'nın torch>=1.13 beyanına göre >=2.0 destek daralması release kararı olarak açıkça duyurulmalıdır. Bu görevde destek genişletilmedi, API migration veya yeni özellik başlatılmadı.
